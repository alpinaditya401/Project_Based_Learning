##### 2. TanStack Query Service (`src/services/api.ts`)
**Size:** 8,421 bytes

**Architecture:**
- API client dengan axios interceptor
- Query keys organization pattern
- Typed query/mutation hooks
- Stale time configurations

**Query Keys Structure:**
```typescript
queryKeys = {
  sensors: { all, lists, list(filters), details(id) },
  devices: { all, list, details(deviceId) },
  alerts: { all, list, recent() },
  schedules: { all, list, details(scheduleId) },
  thresholds: { all, list, details() }
}
```

**Custom Queries Implemented:**
1. ✅ `useSensorReadings()` - 30s staleTime, real-time capable
2. ✅ `useRecentSensorData()` - 10s staleTime, 5s refetch interval
3. ✅ `useDevices()` - 1min staleTime for device list
4. ✅ `useAlerts()` - 30s staleTime for urgent updates
5. ✅ `useFeedingSchedules()` - 5min staleTime for configs
6. ✅ `useThresholdSettings()` - 1hr staleTime for stable settings

**Mutation Patterns:**
- ✅ `useAcknowledgeAlert()` - Alert management
- ✅ `useUpdateThreshold()` - Configuration update
- ✅ `useSendActuatorCommand()` - Device control

**Cache Strategy:**
- Fresh data untuk monitoring (alerts, sensors)
- Medium cache untuk configs (devices, thresholds)
- Long cache untuk stable data (schedules)

## 🎯 BEST PRACTICES APPLIED

### Development Standards

1. **TypeScript Strict Mode**: All files typed dengan proper interfaces
2. **Component Composition**: Small, reusable, single-responsibility components
3. **Separation of Concerns**: Logic, UI, and services terpisah jelas
4. **Naming Conventions**: Clear, consistent naming patterns
5. **Error Handling**: Try-catch blocks dengan meaningful error messages

### Performance Optimizations

1. **Server Components**: Default to RSC untuk data fetching
2. **Parallel Fetching**: Use Promise.all untuk concurrent requests
3. **Caching Strategies**: Optimal staleTime per query type
4. **Code Splitting**: Automatic dengan Next.js routing
5. **Bundle Optimization**: Tree-shakeable imports

### Security Measures

1. **Authentication Check**: Server-side di middleware
2. **Input Validation**: Client-side dengan Zod pattern
3. **CSP Headers**: Strict content security policy
4. **Rate Limiting**: Prepared untuk implementation
5. **XSS Prevention**: Sanitized outputs, no innerHTML
